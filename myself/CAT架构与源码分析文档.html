一、项目整体架构

CAT 是大众点评开源的实时应用监控系统,提供 Transaction / Event / Heartbeat / Metric 四类消息的采集、传输、聚合、告警与可视化。

1.2 核心工作原理

CAT 的核心思想是 "客户端埋点 → TCP 异步上报 → 服务端实时分桶聚合 → 报告落盘":

  1. 客户端:业务代码通过 Cat.newTransaction() 等 API 在 ThreadLocal 中构建 MessageTree,事务 complete() 时通过 TcpSocketSender 异步入队,后台线程用 Netty 以 NT1 二进制协议发送到服务端。
  2. 服务端:Netty ServerBootstrap 在 2280 端口收字节流 → MessageDecoder 长度分帧解码 → DefaultMessageHandler 同步调用 RealtimeConsumer.consume() → 按消息时间戳定位 Period(1 小时一桶) → 按 domain.hashCode() 分流到每个 Analyzer 类型独立的 ArrayBlockingQueue(30000) → PeriodTask 线程消费 → 各 Analyzer process() 累积到内存 Report → 周期结束 doCheckpoint(true) 落盘(本地文件 + MySQL)。

1.3 多语言客户端与集成

  • lib/ 目录提供多语言 SDK:C / C++ / Go(v1、v2) / Python / Node.js / C# / Erlang。大部分语言基于 ccat C 库通过 FFI 调用。
  • integration/ 目录提供主流框架的集成适配:
    • Spring / SpringBoot / SpringMVC-AOP:CatAspect 切面自动埋点
    • Apache Dubbo / Dubbo:CatFilter 集成 RPC 调用链
    • MyBatis:CatMybatisPlugin 拦截 SQL
    • Druid:DruidCatFilter 数据源监控
    • Log4j / Log4j2 / Logback:CatAppender 把日志作为 Event 上报
    • Elasticsearch-Jetty:集成 ES 查询
    • Context:CatContextImpl 用于跨服务传递 CAT 上下文(支持分布式调用链)

二、服务端启动流程源码分析

2.1 服务端架构

CAT 服务端采用分层流水线 + 时间分桶 + 多 Analyzer 并行的架构,核心由"接收 → 分发 → 分析 → 存储"四层组成,通过 PeriodManager 按小时切分周期,实现高吞吐实时聚合。

四层分层架构

┌─────────────────────────────────────────────────────────────────────┐
│  ① 接收层 (Network Layer)                                            │
│    TcpSocketReceiver (Netty ServerBootstrap, 端口 2280)              │
│    ├─ bossGroup / workerGroup 各 24 线程 (Linux 用 Epoll)            │
│    └─ MessageDecoder (ByteToMessageDecoder)                         │
│         └─ 半包处理 + CodecHandler 分派 (NT1/PT1) → DefaultMessageTree │
└──────────────────────────┬──────────────────────────────────────────┘
                           ▼ (Netty worker 线程内同步调用)
┌─────────────────────────────────────────────────────────────────────┐
│  ② 分发层 (Dispatch Layer)                                          │
│    DefaultMessageHandler → RealtimeConsumer.consume(tree)            │
│    └─ PeriodManager.findPeriod(timestamp)  ← 按消息时间戳定位小时桶   │
│    └─ Period.distribute(tree)                                        │
│         ├─ 按 domain.hashCode() % tasks.size() 分流(同 domain 同实例)│
│         ├─ 一个 tree 广播到全部 12 个 analyzer 类型                   │
│         └─ 队列满则故障转移到下一 task                                │
└──────────────────────────┬──────────────────────────────────────────┘
                           ▼ (ArrayBlockingQueue, 容量 30000, offer 非阻塞)
┌─────────────────────────────────────────────────────────────────────┐
│  ③ 分析层 (Analysis Layer)                                          │
│    PeriodTask 线程(默认每 analyzer 2 个)→ AbstractMessageAnalyzer    │
│    └─ analyze(queue): while(!isTimeout()) poll + process(tree)      │
│    └─ 12 种 Analyzer 并行:                                          │
│       transaction / event / problem / heartbeat / dump / state /   │
│       cross / matrix / dependency / storage / top / business        │
│    └─ 累积到内存 Report(TransactionReport / EventReport / ...)      │
└──────────────────────────┬──────────────────────────────────────────┘
                           ▼ (周期结束 doCheckpoint)
┌─────────────────────────────────────────────────────────────────────┐
│  ④ 存储层 (Storage Layer)                                           │
│    ReportManager → storeHourlyReports(startTime, policy, index)    │
│    ├─ LocalReportBucket  → 本地文件 ${CAT_HOME}/bucket/...          │
│    └─ HourlyReportDao    → MySQL (FILE_AND_DB 时)                  │
│    Dump 专用:MessageDumperManager → LocalMessageBucketManager      │
└─────────────────────────────────────────────────────────────────────┘

线程模型

线程/池数量职责
Netty bossGroup24接受客户端连接
Netty workerGroup24读取/解码/分发消息(同步调用 consume)
PeriodManager1每秒轮询,按小时启停 Period
PeriodTask12 类型 × 2(默认)消费各 analyzer 队列,执行 process
EndTaskThread临时周期结束时异步 finish + 落盘

周期(Period)机制

  • 时长:1 小时一个 Period(RealtimeConsumer.HOUR)。
  • 预启动:当前周期结束前 3 分钟(aheadTime)启动下一周期,保证跨小时消息无缝接入。
  • 宽限:周期结束后再宽限 3 分钟(extraTime)处理迟到消息,之后才真正 finish。
  • 触发方式:PeriodManager.run() 用 Thread.sleep(1000) 轮询 + PeriodStrategy 状态机(非 Timer/ScheduledExecutor)。

12 种 Analyzer 体系

同一棵 MessageTree 会被广播到全部 12 种 analyzer 队列并行处理,各 analyzer 职责单一:

AnalyzerID职责
TransactionAnalyzertransaction事务耗时/次数/区间分布聚合
EventAnalyzerevent事件计数聚合
ProblemAnalyzerproblem问题检测(长请求、错误、LongSQL 等)
HeartbeatAnalyzerheartbeat客户端心跳状态聚合
DumpAnalyzerdump原始消息转储(走 MessageDumperManager,非 ReportManager)
StateAnalyzerstate客户端状态分析
CrossAnalyzercross服务调用关系分析
MatrixAnalyzermatrix矩阵分析(调用路径聚合)
DependencyAnalyzerdependency服务依赖分析
StorageAnalyzerstorage存储分析(SQL/Cache/RPC)
TopAnalyzertopTop 排序分析(优先处理)
BusinessAnalyzerbusiness业务指标分析

存储架构

  • 中途 checkpoint:doCheckpoint(false) → 仅写本地文件(FILE),JVM shutdown hook 触发。
  • 周期结束:doCheckpoint(true) → 同时写本地文件 + MySQL(FILE_AND_DB)。
  • 本地文件:LocalReportBucket 写到 ${CAT_HOME}/bucket/{analyzer}/{domain}/{hour}/,采用 snappy 压缩。
  • Dump 特殊:DumpAnalyzer 不走 ReportManager,用 MessageDumperManager + LocalMessageBucketManager 存储原始消息,支持 logview 查询。

2.2 启动入口(非 Listener,而是 Servlet)

web.xml 配置 cat-home/src/main/webapp/WEB-INF/web.xml 中 cat-servlet 的 load-on-startup=1:

<servlet>
    <servlet-name>cat-servlet</servlet-name>
    <servlet-class>com.dianping.cat.servlet.CatServlet</servlet-class>
    <load-on-startup>1</load-on-startup>
</servlet>

CatServlet.java 继承 unidal 框架的 AbstractContainerServlet,核心 initComponents():

protected void initComponents(ServletConfig servletConfig) throws ServletException {
    ModuleContext ctx = new DefaultModuleContext(getContainer());
    ModuleInitializer initializer = ctx.lookup(ModuleInitializer.class);
    ctx.setAttribute("cat-client-config-file", getConfigFile(..., "client.xml"));
    ctx.setAttribute("cat-server-config-file", getConfigFile(..., "server.xml"));
    initializer.execute(ctx);   // 触发整个 Module 体系
}

2.3 Module 体系与依赖链

unidal 框架通过 Module 接口 + ModuleInitializer 按依赖深度优先执行,顶层模块在 ComponentsConfigurator.java 中注册为 cat-home:

CatHomeModule (顶层)
├── CatConsumerModule ── CatCoreModule ── CatClientModule
└── CatHadoopModule   ── CatCoreModule ── CatClientModule

AbstractModule 的两个核心方法:

  • setup(ctx):在所有 execute() 之前执行,仅顶层模块调用。
  • execute(ctx):按依赖深度优先顺序,叶子模块先执行。

2.4 完整启动时序

阶段 1 — CatHomeModule.setup() 最先执行(启动 Netty)

文件:CatHomeModule.java

protected void setup(ModuleContext ctx) throws Exception {
    final TcpSocketReceiver messageReceiver = ctx.lookup(TcpSocketReceiver.class);
    messageReceiver.init();         // ★ 启动 Netty 2280
    Runtime.getRuntime().addShutdownHook(... messageReceiver.destory() ...);
}

文件:TcpSocketReceiver.java 用 Netty ServerBootstrap:

private int m_port = 2280;   // 默认端口,硬编码
public synchronized void startServer(int port) {
    boolean linux = getOSMatches("Linux");
    int threads = 24;
    ServerBootstrap bootstrap = new ServerBootstrap();
    m_bossGroup   = linux ? new EpollEventLoopGroup(threads) : new NioEventLoopGroup(threads);
    m_workerGroup = linux ? new EpollEventLoopGroup(threads) : new NioEventLoopGroup(threads);
    bootstrap.group(m_bossGroup, m_workerGroup)
             .channel(linux ? EpollServerSocketChannel.class : NioServerSocketChannel.class)
             .childHandler(new ChannelInitializer<SocketChannel>() {
                 protected void initChannel(SocketChannel ch) {
                     ch.pipeline()
                       .addLast("decode", new MessageDecoder())        // 内部类
                       .addLast("encode", new ClientMessageEncoder());
                 }
             })
             .childOption(ChannelOption.SO_KEEPALIVE, true)
             .childOption(ChannelOption.TCP_NODELAY, true)
             .childOption(ChannelOption.ALLOCATOR, PooledByteBufAllocator.DEFAULT);
    m_future = bootstrap.bind(port).sync();   // 绑定 2280
}

阶段 3 — RealtimeConsumer.initialize() 启动消息处理引擎

文件:RealtimeConsumer.java

public static final long HOUR = 60 * 60 * 1000L;

public void initialize() throws InitializationException {
    m_periodManager = new PeriodManager(HOUR, m_analyzerManager, m_serverStateManager, m_logger);
    m_periodManager.init();                          // 启动第一个 Period
    Threads.forGroup("cat").start(m_periodManager);  // 启动周期管理线程
}

文件:PeriodManager.java 用 Thread.sleep(1000) 轮询 + PeriodStrategy 状态机(不是 Timer/ScheduledExecutor):

public void run() {
    while (m_active) {
        long now = System.currentTimeMillis();
        long value = m_strategy.next(now);   // 正=开新周期,负=结束旧周期,0=无操作
        if (value > 0)      startPeriod(value);
        else if (value < 0) Threads.forGroup("cat").start(new EndTaskThread(-value));
        Thread.sleep(1000L);                  // 每秒轮询
    }
}

PeriodStrategy(duration=1H, extraTime=3min, aheadTime=3min) 在当前周期结束前 3 分钟预启动下一周期,保证跨小时无缝。

三、客户端启动流程源码分析

3.1 客户端架构

CAT 客户端采用门面 API + ThreadLocal 上下文 + 异步队列 + Netty 通信的分层架构,核心由五层组成,通过双队列 + 后台线程实现业务线程与网络的解耦。

五层分层架构

┌─────────────────────────────────────────────────────────────────────┐
│  ① API 门面层 (Facade Layer)                                         │
│    Cat (静态门面,懒加载)                                            │
│    └─ Cat.newTransaction / logEvent / logError / logMetric / logHeartbeat│
│         └─ DefaultMessageProducer (薄封装,无状态)                   │
└──────────────────────────┬──────────────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────────────┐
│  ② 上下文管理层 (Context Layer)                                      │
│    DefaultMessageManager                                             │
│    └─ ThreadLocal<Context> (每线程一个)                              │
│         ├─ Context 内含 MessageTree + Stack<Transaction>             │
│         ├─ start(tran):压栈 / 作为子节点                              │
│         └─ end(tran):pop 栈,栈空时 copy(tree) → flush                │
│    └─ MessageIdFactory (mmap 持久化 mark 文件,ID 格式 domain-ipHex-hour-index)│
└──────────────────────────┬──────────────────────────────────────────┘
                           ▼ flush(tree)
┌─────────────────────────────────────────────────────────────────────┐
│  ③ 异步发送层 (Sender Layer)                                         │
│    TcpSocketSender (MessageSender 实现,同时是后台 Task)              │
│    ├─ 双队列:ArrayBlockingQueue(5000) × 2                          │
│    │   ├─ m_queue       (普通消息)                                  │
│    │   └─ m_atomicQueue (原子消息,可合并)                           │
│    ├─ 采样丢弃:canDiscard && ratio<1.0 && !hitSample → LocalAggregator│
│    └─ 原子消息合并:30s 或 200 条触发,打包成 _CatMergeTree           │
└──────────────────────────┬──────────────────────────────────────────┘
                           ▼ 后台线程 poll + encode
┌─────────────────────────────────────────────────────────────────────┐
│  ④ 编码层 (Codec Layer)                                             │
│    NativeMessageCodec (ID = "NT1", 二进制协议)                      │
│    └─ [4字节长度][NT1][10个HEADER字符串][消息体 t/T/E/M/H/L]        │
│       数值用 LEB128 varint,字符串用 varint+UTF8                     │
│    └─ 输出 Netty ByteBuf (PooledByteBufAllocator)                   │
└──────────────────────────┬──────────────────────────────────────────┘
                           ▼ channel.writeAndFlush(buf)
┌─────────────────────────────────────────────────────────────────────┐
│  ⑤ 网络通信层 (Transport Layer)                                     │
│    ChannelManager (Netty Bootstrap, NioSocketChannel)               │
│    ├─ Netty pipeline 为空(无 encoder,直接写 ByteBuf)               │
│    ├─ 路由热更新:每 10s 对比 routers 配置,变化则重建 channel       │
│    ├─ 断连检测:连续 3 次 stalled 才关闭                             │
│    └─ 重连:强制掰回默认服务器,最多 20 次重试                        │
└─────────────────────────────────────────────────────────────────────┘

DefaultTransportManager装配 TcpSocketSender,收集启用的 server 地址cat-client/.../DefaultTransportManager.java

线程模型

线程数量职责
业务线程N(应用)构造 MessageTree,complete 时 offer 入队(非阻塞,不等待网络)
cat-TcpSocketSender1轮询队列,合并原子消息,编码 + writeAndFlush
cat-ChannelManager1每 10s 路由检查 / 断连检测 / 重连 / saveMark
Netty NioEventLoopGroup1实际 TCP 读写(daemon 线程)
StatusUpdateTask1每 60s 心跳上报,每 3 分钟刷新路由配置
LocalAggregator.DataUploader1采样丢弃消息的本地聚合后上传

MessageTree 与 ThreadLocal 上下文

  • 无独立 ContextManager:cat-client 中没有 ContextManager 类,线程上下文由 DefaultMessageManager 的私有字段 ThreadLocal<Context> m_context 直接管理,内部类 Context 持有 MessageTree m_tree + Stack<Transaction> m_stack。
  • 栈式嵌套:newTransaction 时 start 压栈并作为父事务子节点;根事务直接 tree.setMessage。
  • complete 触发 flush:end 弹栈,栈空时 tree.copy() 后 flush(浅拷贝,主线程复用 tree 容器)。
  • 树保护:节点数 ≥ 2000 跨小时则 truncateAndFlush(打包发送 + Next 事件链接);≥ 5000 强制清空。

双队列发送机制

  • 普通队列 m_queue:容量 5000,后台线程 poll(5ms) 取出后 sendInternal。
  • 原子队列 m_atomicQueue:同类原子消息(如 Metric)累积 30 秒或 200 条触发合并,打包成一个 _CatMergeTree 事务再入普通队列,大幅减少网络包。
  • 非阻塞 offer:队列满立即返回 false,统计 loss,不阻塞业务线程。
  • 采样降级:canDiscard=true(普通 Transaction/Event)在采样率<1.0 且未命中时走 LocalAggregator 本地聚合,完全不占网络;setDiscard(false)(Error/Heartbeat/Metric)强制上报。

路由与重连机制

  • 动态路由:DefaultClientConfigManager.refreshConfig() 通过 HTTP 拉 http://{server}:{httpPort}/cat/s/router?op=json 获取 routers(分号分隔的 ip:port)、block、sample。
  • 热更新:ChannelManager 每 10 秒比较 getRouters() 与本地缓存,变化则 initChannel 重建连接。
  • 断连检测:通道不活跃累计 m_channelStalledTimes,连续 3 次才真正关闭,避免偶发抖动误判。
  • 强制重连默认服务器:reconnectDefaultServer 注释明确"强制把上报的 channel 掰回默认的(第一台)",在原 server 列表随机选,最多重试 20 次。
  • MessageId 持久化:MessageIdFactory 用 mmap(1MB)把当前小时戳+计数写到 cat-{domain}.mark,每 10 秒 saveMark,重启同小时 index+1000 续接避免 ID 冲突。

public void send(MessageTree tree) {
    if (!m_configManager.isBlock()) {     // 全局阻塞开关

(2) 后台轮询发送(不是定时批量,而是 5ms 忙循环)

public void run() {
    m_active = true;
    while (m_active) {
        processAtomicMessage();    // 合并原子队列(30s 或 200 条触发)
        processNormalMessage();    // 发送普通队列
    }
    processAtomicMessage();
    while (true) { /* drain 残留 */ }
}
private void processNormalMessage() {
    ChannelFuture channel = m_channelManager.channel();
    if (channel != null) {
        MessageTree tree = m_queue.poll();
        if (tree != null) {
            sendInternal(channel, tree);
            tree.setMessage(null);  // 释放引用
        } else { Thread.sleep(5); }
    } else { Thread.sleep(5); }     // 等 channel 重连
}

(3) NativeMessageCodec NT1 协议

文件:NativeMessageCodec.java

+----+----+----+--------+--------+----+----+--------+--------+--------+--------+--------+--------+--------+--------+---------+--------+---------+---------+---------+---------+---------+
| L1 | L2 | L3 | L4 (4字节长度,值为后续字节数) |  'N'| 'T'| '1' | domain(varstr) | hostName | ipAddress | threadGroupName | threadId | threadName | messageId | parentMessageId | rootMessageId | sessionToken | 消息体(递归 t/T/E/M/H/L) |
+----+----+----+--------+--------+----+----+--------+--------+--------+--------+--------+--------+--------+--------+--------+---------+--------+---------+---------+---------+---------+---------+
  • varstr = varint(长度) + UTF-8 bytes
  • 数值(timestamp/duration)用 LEB128 varint(类 Protobuf,小数值省字节)
  • 消息类型字节:'t' 事务开始 / 'T' 事务结束 / 'E' 事件 / 'M' 指标 / 'H' 心跳 / 'L' Trace

(4) 原子消息合并

每 30 秒或累积 200 条触发,把多条原子消息打包成一个 _CatMergeTree 事务,大幅减少网络包数量。

5.2 服务端接收端关键源码

(1) 半包解码

文件:TcpSocketReceiver.MessageDecoder 继承 Netty ByteToMessageDecoder:

protected void decode(ChannelHandlerContext ctx, ByteBuf buffer, List<Object> out) {
    if (buffer.readableBytes() < 4) return;           // 不足 4 字节,等
    buffer.markReaderIndex();
    int length = buffer.readInt();                    // 读 4 字节长度
    buffer.resetReaderIndex();
    if (buffer.readableBytes() < length + 4) return; // 不够一帧,等

    if (length > 0) {
        ByteBuf readBytes = buffer.readBytes(length + 4);
        DefaultMessageTree tree = (DefaultMessageTree) CodecHandler.decode(readBytes);
        tree.setBuffer(readBytes);      // 保留 buffer 给 DumpAnalyzer
        m_handler.handle(tree);         // 同步调用,在 Netty worker 线程内
        if (++m_processCount % 1000 == 0) {
            m_serverStateManager.addMessageTotal(1000);
        }
    }
}

(2) 按 domain hash 分流(同一消息广播到所有 analyzer)

文件:Period.distribute()

public void distribute(MessageTree tree) {
    m_serverStateManager.addMessageTotal(tree.getDomain(), 1);
    String domain = tree.getDomain();
    boolean success = true;
    for (Entry<String, List<PeriodTask>> entry : m_tasks.entrySet()) {
        List<PeriodTask> tasks = entry.getValue();
        int index = 0;
        boolean manyTasks = tasks.size() > 1;
        if (manyTasks) index = Math.abs(domain.hashCode()) % length;  // 同 domain 进同 analyzer
        boolean ok = tasks.get(index).enqueue(tree);
        if (!ok && manyTasks) {
            ok = tasks.get((index + 1) % length).enqueue(tree);  // 故障转移
        }
        if (!ok) success = false;
    }
    if (!success && !tree.isProcessLoss()) {
        m_serverStateManager.addMessageTotalLoss(tree.getDomain(), 1);
        tree.setProcessLoss(true);
    }
}

(3) 分析循环 + 周期 checkpoint

文件:AbstractMessageAnalyzer

public void analyze(MessageQueue queue) {
    while (!isTimeout() && isActive()) {
        MessageTree tree = queue.poll();
        if (tree != null) {
            try { process(tree); }
            catch (Throwable e) { if (++m_errors==1 || m_errors%10000==0) Cat.logError(e); }
        }
    }
    while (true) {                     // 超时后 drain 残留
        MessageTree tree = queue.poll();
        if (tree == null) break;
        try { process(tree); } catch (...) { }
    }
}
public synchronized void doCheckpoint(boolean atEnd) {
    if (atEnd && !isLocalMode()) {
        m_reportManager.storeHourlyReports(getStartTime(), FILE_AND_DB, m_index);
    } else {
        m_reportManager.storeHourlyReports(getStartTime(), FILE, m_index);
    }
}

六、设计要点总结

  1. 客户端全异步 + 采样降级:ArrayBlockingQueue.offer 非阻塞(满则丢)保证业务线程不被阻塞;采样率<1.0 时通过 LocalAggregator 在客户端本地聚合,完全不占网络。
  2. Netty pipeline 为空:客户端依赖业务线程外预先 NativeMessageCodec.encode 出 ByteBuf,直接 writeAndFlush,无需 encoder。
  3. 服务端无全局队列:Netty worker 线程同步调用 RealtimeConsumer.consume → 直接按时间戳定位 Period → 按 domain hash 入对应 analyzer 队列。避免全局锁竞争。
  4. 按时间分桶 + 预启动:1 小时一个 Period,提前 3 分钟启动下一周期,宽限 3 分钟处理迟到消息,保证跨小时无缝。
  5. 同 domain 同 analyzer:hash 取模分流,保证同一 domain 的消息进同一 analyzer 实例,减少锁竞争且保证报告一致。
  6. 多 analyzer 并行消费:一棵 MessageTree 广播到 12 种 analyzer 队列并行处理,各 analyzer 职责单一。
  7. 周期结束双写:atEnd=true 时同时写本地文件和 MySQL,中途 checkpoint 仅写文件。
  8. 路由热更新:客户端每 10 秒比较服务端下发的 routers 配置,变化则重建 channel;服务端通过 /cat/s/router?op=json HTTP 接口下发。
